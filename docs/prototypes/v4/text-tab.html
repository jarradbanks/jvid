Text Tab

The Inspector's Text tab for a selected title clip (#259). Every mockup is drawn at the Inspector's real width: 288px, which is what default_dock() gives at 1280×720, with a 240px toggle for the 960×600 minimum window where the panel hits PANEL_MIN. The dashed line marks where a 1280×720 window cuts the panel off.

The sample is a long three-line title with every style on: Size changed from 96 to 120, Position animated with a key at the playhead, a 4px black outline, a 60% black shadow and a 50% black box. Sliders drag, sections fold, swatches open the picker, and the boxes grow as you type.

What's Wrong Now

  • The text box is a two-row egui TextEdit that doesn't fill the width or grow, so a three-line title scrolls inside a box shorter than the title.
  • Size and Weight share one row, with Size's keyframe toggle wedged between them. Weight has no keyframe and no label column.
  • Left, Center and Right are unlabelled selectable text buttons on a row of their own; nothing says they're alignment.
  • Colours use egui's color_edit_button, which paints half solid and half checkerboard even for opaque white, so every swatch looks partly transparent.
  • Each row is ui.horizontal with its own label width, so fields start at a different x on every row and stock DragValues sit beside house fields.
  • There are no sections: Outline, Outline Color, Shadow, Shadow Color, Box Padding and Box Color are eleven loose rows.

Alternatives

All three share the row rules under them. They differ in how the five groups the issue names (Text, Fill, Outline, Shadow, Box) are arranged.

Row rules for all three

  • One label column. 72px, Ink 2. Every field starts at the same x on every row, in every section.
  • Two tool slots per row: Reset (shown only when the value differs from its default; the slot stays reserved) and one keyframe diamond. At 288px there's no room for v3's keyframe arrows as well, so Previous and Next Keyframe move into the diamond's right-click menu beside the easing.
  • Sliders for ranged values: Size (slider covers 8–400; the field still takes 1–1000), Weight (100–900 in steps of 100, with ticks), Outline Width (0–32) and Box Padding (0–200). When the value column drops under about 112px, as it does at 240px, the sliders give way and the fields still drag and type.
  • Align is a labelled segmented control of three icons, with Left, Center and Right as tooltips.
  • One swatch: 24px, 6px corners, 1px Border Strong, then the hex in a field. A checkerboard shows only behind a colour with alpha under 100%, and the alpha shows after the hex. A fully transparent colour reads None.
  • The text box is full width, at least two lines, grows one line at a time up to eight, then scrolls. Enter adds a line; it isn't in a section, so folding Text never hides the words.

Swatches

One component for Fill, Outline, Shadow and Box, at row size and at 40px to show the drawing. In egui it's a rounded RectShape filled from a repeating 2×2 checker texture, then the colour on top, then the 1px stroke, so the checker keeps the 6px corners.

Colour Picker Open

Clicking a swatch or its hex opens egui's picker as a popover under the row: saturation and value square, hue strip, alpha strip over the checker, and hex and alpha fields. A drag is one undo step. Here it's open on Box Color in A.

Missing Font and Font Search

A project made on another machine can name a font that isn't installed. At 288px "Bebas Neue (missing)" doesn't fit the field, so the Amber warning icon carries "missing" and the tooltip names the font and the fallback. The family name stays in Ink, untruncated where it fits. Clicking opens the existing search, which previews the highlighted family in the Program view.

A at Both Widths

The recommended layout at 288px and at 240px, sections open. At 240 the value column is 92px: sliders hide, the hex field drops the alpha, and Position's and Offset's X and Y prefixes drop so 0.82 fits a 44px field; their tooltips still name them.

Recommendation: A, Sections Like the Video Tab

A is the only one that makes the Text tab look like the rest of the Inspector rather than a special case, and it's the cheapest to build: it reuses the inspector rows and section heads that already exist, so Text gains the remembered open state, the reset-when-changed slot and the single diamond for free. The issue asks for exactly these five sections.

It takes one idea from the others: a collapsed section shows its summary in Ink 3 (Shadow above reads "3, 3 · 60%"), so folding Outline, Shadow and Box keeps their state visible and A fits a 720p panel. First run opens Text and Fill; the rest remember what the user last did.

B's checkbox needs an enabled flag on each style that the Text model doesn't have, and one diamond for two values breaks the per-property keyframes. C is the nicest for typing but hides keyframing and invents a pattern no other tab uses.

Build Notes

  • Text box: TextEdit::multiline at available_width, desired_rows set from the line count (2 to 8), house Field frame.
  • Rows: the existing inspector row helper (72px label, values, tools). Size, Weight, Outline Width and Box Padding use its slider; Weight steps by 100.
  • Align: a three-segment icon control in suite-ui, 24px tall, Raised fill on the chosen segment.
  • Swatch: a suite-ui widget replacing color_edit_button_srgba_unmultiplied; it opens egui's color_picker_color32 in a popover. Unchanged undo behaviour: one step per drag.
  • Collapsed summary: Ink 3, truncated with an ellipsis, between the title and the tools.
